When `tla.compile` fails at lowering with `TlaLoweringError: type_args length must match function arguments: expected N, got M`, count the kernel's full parameter list (Tensor and Constexpr alike) and compare it with the number of compile-time samples you passed before touching the kernel body. Repair by passing one sample per parameter, positionally, appending the constexpr values after the tensors — e.g. `tla.compile(probe, tx, ty, tt, ROWS, COLS, options=...)` — so the sample count equals `len(arg_names)`. Do not add a `type_args=` keyword to `tla.compile`; it raises `TypeError` instead of compiling. This applies only at the lowering arity stage: a successful compile does not attest device numerics, so still launch with `block_num=...` and compare output against an independent reference.

When writing a Catlass TLA vector kernel in simt mode, nest a tla.vec.func(mode="simt", thread_block_dim=N) context inside the tla.vector() region (not the reverse), and put the tla.arch.thread_idx()/tla.arch.thread_block_dim() calls that drive the per-lane loop inside that simt context. Observed failure modes are a simt block placed directly under tla.kernel (reported as needing nesting inside tla.vector()) and thread intrinsics used directly under tla.vector() (reported as only available inside a tla.vec.func with mode='simt'). Also verify the per-element work is semantically correct: correct region nesting only unblocks lowering, and a body that ignores the index tensor still fails the reference check. This guidance is inferred from one gather-style operation in simt mode; other operations and execution modes are untested here.

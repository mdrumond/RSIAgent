A5 Catlass SIMT scalar indexing into a rank-2 tensor buffer: index with a coordinate of the same rank, not a single flattened index. When lowering of a simt `tla.vec.func` body fails with `tla.scalar_load index rank must match tensor logical rank (shape rank 2, index rank 1)`, the rejected site is the scalar read whose index tuple is shorter than the tensor's logical rank, e.g. `x[base + j]` on a 33x129 buffer (base = r * cols_i32). Either address the element with a full-rank coordinate built from the loop indices (e.g. `x[r, j]`) or pass a rank-1 descriptor for the same storage and keep the flat index. Scope only to that exact error and to the scalar load site it points at: the enclosing dynamic `tla.range` loops, the SIMT/vector nesting, block_num (1 and 40), thread count and lens values were not the discriminating factor and need no change. Rank-1 buffers (`lens`, `scale`, `out`) indexed as `lens[r]`, `scale[r]`, `out[r]` are already rank-consistent and are not part of this rule. This rests on the archived lowering diagnostic plus emulated contrasts only; it is not a device-attested repair, so confirm by compiling and comparing against an independent reference on both 1 and 40 blocks, and treat any further lowering error from the same statement as a separate, unexplained cause rather than assuming the rank change fixed it.

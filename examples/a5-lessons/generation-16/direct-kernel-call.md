When a DSL exposes a `@tla.kernel`-decorated kernel, do not call the decorated object directly from host code and do not invent launcher helpers: direct invocation is rejected at runtime with a TypeError stating direct invocation is disabled, and names such as `tla.launch` do not exist. Compile first with `tla.compile(kernel, *sample_args)`, then launch the returned artifact with `compiled(*runtime_args, block_num=...)`. `tla.compile` requires the kernel's argument samples (or an explicit `type_args`) when the signature is non-empty, so pass the actual device tensors rather than the bare kernel. Keep the kernel body itself unchanged; the correction belongs only in the host launch path. If the target API is genuinely unknown, verify it against the reported runtime rather than guessing an alternative entry point.

When a kernel fails while lowering with a message that a DSL symbol such as a vector scope is only available in lowered MLIR, check the decorated kernel body for a function-local import of its own DSL package: that inner import rebinds the name inside kernel scope, so tracing sees plain Python instead of the traced API. The pair supports treating that shadowing import, not the DSL construct, as the likely cause, since the kernel arithmetic and launch are otherwise identical and dropping the inner import is the only change. Check your own revision by reading the kernel body before rerunning: bind the DSL name once at module level and do not re-import it inside the decorated function, then confirm compilation succeeds and the result matches an independent CPU reference, because a wrong-value mismatch points to a different defect.

# Evidence-driven memory maintenance

Source-approved memories publish directly to the KDB. There is no memory A/B
admission step. Normal project verification reviews the exact memory versions
actually delivered to each actor.

The KDB companion ledger retains access events globally and per actor, immutable
version statistics, lifetime lineage, correctness/usefulness judgments, and
retirement evidence. Real repeated delivery counts; replay of the same durable
tool result does not. Internal search candidates and verifier/curriculum reads
are not actor accesses. Inline memory, selected KDB excerpts, and subsequently
read linked content are recorded. Unknown usefulness does not lower the rate.

Every project review supplies `memory_judgments`, `memory_resolutions`, and
`retirement_checks` arrays; empty arrays are valid when no entries apply.
Correctness decisions require reading the complete exact memory document and
independent project evidence. A cited contradiction quarantines that version
immediately, including stale actor snapshots. Ordinary uncertainty stays unknown;
`investigate: true` requests an explicit evidence-backed investigation.

A current version with at least ten decided actor/project exposures and a useful
fraction below 30% receives a required rewrite project. Correct but unhelpful
memory stays available. Correctness repairs take priority over investigations,
which take priority over usefulness rewrites. Curriculum authors must address the
imposed obligation before ordinary work. They and the assigned actor receive the
exact disputed claim and counterevidence as untrusted repair artifacts, outside
normal retrieval; quarantine does not prevent that bounded investigation.

Passing a kernel does not resolve a memory obligation. Source-reviewed projects
must explicitly replace, restore, retire, or confirm the disputed version.
Replacement must change consumable content. Confirmation only closes an active
investigation without changing its version or counters. New versions begin fresh
version counters; lifetime counters and resolved maintenance episodes remain.

Retirement is permanent history rather than deletion. Future source reviews
compare proposed claims with retired records. Reintroducing a retired claim
requires fresh evidence explicitly resolving its recorded counterevidence.
Shared artifact retention lets another campaign investigate or resume maintenance
without access to the original campaign's live working directory. Durable review
and resolution receipts recover interruptions without another admission run.

Campaign reports and the dashboard expose lifecycle, version/lifetime and per-actor
statistics, maintenance obligations, and retirement reasons.
